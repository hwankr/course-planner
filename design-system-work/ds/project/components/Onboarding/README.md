The two-step first-run wizard (header, stepper, 학과 및 입학 정보 and 졸업 요건 설정 Cards with the 복수전공/부전공 toggles) plus the profile banner that shows its result.

## Use it for / don't use it for

- Use the wizard once, at `/onboarding`, while a signed-in user's `onboardingCompleted` is false or a guest profile is empty (OnboardingGuard redirects there): it collects department, enrollment year, major type (step 1) and graduation credits (step 2), then the app goes to `/planner`.
- Use the 복수전공 / 부전공 toggle pair wherever the major type is edited: the same markup is repeated in the profile 전공 설정 Card, guest and authenticated.
- Use the gradient banner only at the top of the authenticated profile, above the 기본 정보 Card; the guest profile has no banner.
- Don't extend the stepper (two circles and one connector are hard-coded) and don't reuse the colored top rail without a Card: it is `border-t-4` on the Card itself.

## What the consumer provides

- No component, no props: `OnboardingPage` and `ProfilePage` are default-exported pages that own their state. The static pieces follow `step: number` (1 or 2), `majorType: MajorType` (`'single' | 'double' | 'minor'`, default `'single'`), `availableMajorTypes: MajorType[]` (default all three; a toggle renders only when its type is listed and the block only once `departmentId` is set), `secondaryDepartmentId`, `enrollmentYear: string`, `requirementYear` (default `DEFAULT_REQUIREMENT_YEAR` = 2025, options 2025 / 2026), the credit numbers (defaults 120 / 30 / 63 / 24, double 36 / 12, minor 21 / 9 / 0, earned 0), `autoFillMessage`, `error` and `completeMutation.isPending`.
- Composed primitives: `Card`, `CardHeader`, `CardTitle`, `CardContent`; `Input` with `type="number"`, `min` and `max`; `Button` default and `variant="outline"`; `SearchableSelect` with `options`, `value`, `onChange`, `placeholder`, `disabled`. Lucide icons: School, GraduationCap, Check, BookOpen, Award, ArrowRight, ArrowLeft, CheckCircle, AlertTriangle; Building2 and CalendarDays on the banner.
- Banner data: `userProfile.name` (initial from `charAt(0).toUpperCase()`, fallback `U`; name fallback 사용자), `department.name`, `enrollmentYear`, `majorType`, `secondaryDepartment.name`.
- Container: the dashboard `<main>` on `gray-50`. The wizard is a `container-2xl` (672px) column with `space-y-8`, centered in a `min-h-[60vh]` flex box with `space-4` side padding; the banner sits in the profile's `container-2xl` column with `space-y-6`.

## Accessibility

- lucide-react renders every icon here (Check, School, GraduationCap, BookOpen, Award, ArrowRight, ArrowLeft, CheckCircle, AlertTriangle, Building2, CalendarDays) with `aria-hidden="true"`, so none is announced: the stepper Check, the toggle Check, 완료's CheckCircle and the badge glyphs are invisible to assistive technology.
- The stepper is `<div>`s and `<span>`s with no `role`, `aria-current`, `aria-label` or list semantics; the done circle holds only the hidden Check, so the completed state is visual only.
- No `<label>` has `htmlFor` and no field an `id`, so labels are not tied to their controls; the SearchableSelect text box and the number inputs are announced by placeholder or value only. The 기준 연도 `<label>` is unassociated too. The 학과 select's clear `<button>` (an inline heroicon X with no title) has no `aria-label`, so it has no accessible name.
- The toggles are real `<button type="button">`s and the disabled one carries the `disabled` attribute, but neither has `aria-pressed`: the on state is conveyed by color, the hidden Check glyph and the label losing its `+ … 추가` wording.
- Error and autofill messages are plain `<p>`s without `role="alert"` or `aria-live`. Keyboard: Input and SearchableSelect show the `yu-cyan` ring on any focus, the year select its 1px `yu-navy` ring, Buttons their currentColor ring; the toggles and the help link keep the browser default focus outline.
- The banner's initial is decorative text, the badges are plain `<span>`s, the name is a real `<h2>` under the page's `<h1>` 프로필.
