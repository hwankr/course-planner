Admin list pattern: dashboard stat and menu Cards, plus the filter bar, Card rows, delete confirmations and empty/error/loading boxes repeated across the admin CRUD pages.

## Use it for / don't use it for

- Use it for the CRUD pages under `/admin`: courses, departments and users follow it end to end; requirements, feedback and patch-notes reuse the header, filter and skeleton recipes around their own lists.
- Use the stat and menu Cards only on the admin dashboard. The four stat accents (`yu-navy`, `green-600`, `purple-600`, `orange-600`) are decorative and carry no meaning elsewhere.
- Don't use it for student-facing lists (the planner has CourseCard and SemesterColumn), and don't swap in the Button or Input components: the admin pages never import them, only Card.

## What the consumer provides

- No component exists; each page owns its state. Dashboard: `selectedYear: number` (`DEFAULT_CURRICULUM_YEAR` = 2026), `stats?: { courseCount, departmentCount, userCount, planCount }`, `isLoading`, and the `adminMenus: { title, description, href }[]` const (six entries).
- Courses: `searchTerm: string` (''), `departmentFilter: string` (''), `categoryFilter: RequirementCategory | ''` (''), `yearFilter: number` (2026), `deletingId: string | null` (null), rows `CourseItem[]` (`code`, `name`, `credits`, `department?`, `semesters`, `category?`, `recommendedYear?`). `CATEGORY_LABELS`, `CATEGORY_COLORS` and `SEMESTER_LABELS` are consts in the page file.
- Departments: `search: string` (''), `deleteConfirmId: string | null` (null), rows `Department[]` (`code`, `name`, `college?`).
- Users: `search: string` (''), `roleFilter: string` ('', options '' · 'student' · 'admin'), `departmentFilter: string` (''), `sortOption: string` ('recent', options 'recent' · 'lastLogin' · 'name'), `expandedUserId: string | null` (null), `deleteConfirmId: string | null` (null), rows `UserItem[]` (`name`, `email`, `department?`, `enrollmentYear?`, `studentId?`, `role`, `provider`, `createdAt`).
- Container: the dashboard layout's `gray-50` frame. The page root is a `space-y-6` stack (24px between header, filters and list); rows and tiles are `Card` from `src/components/ui/Card.tsx`.

## Accessibility

- Icon buttons are native `<button type="button">` with a `title` (`수정`, `삭제`, `상세 정보`). Lucide adds `aria-hidden="true"` to every glyph, so the icon buttons are named only by `title` and the clear-search button has no accessible name.
- Search inputs and filter selects rely on a placeholder or first option; none has a `<label>` or `aria-label`, including the dashboard year select.
- The confirm modal is a plain `<div>` pair: no `role="dialog"`, `aria-modal`, focus trap, Escape or backdrop-click handling; focus stays on the clicked trash button behind the overlay.
- The inline delete swap, loading tiles and stat skeletons are not announced (`aria-live`, `aria-busy` absent). The users row's expand target is a `<div onClick>` with `cursor-pointer`, not focusable.
- Menu Cards are real links (the whole card is the anchor) and take the browser's default focus outline; the Card adds none. Text buttons have no focus style beyond the default.
