Collapsible course-catalog panel for the planner: a header with the curriculum-year badge, count, card/list toggle, custom-course button and collapse chevron, a search field, three rows of filter chips, contextual banners and a scrollable body of draggable course rows (grouped by recommended year/semester, or flat under a filter) with inline add buttons.

## Use it for / don't use it for

- Use it once per planner page, full width above the semester grid, inside a `DndContext` shared with the `SemesterColumn`s (`useDroppable` id `catalog`, each item a `useDraggable` with id `catalog-{courseId}`). Pass `focusedSemester` to switch on the add buttons and the focus banner.
- Don't use it for read-only or shared plan pages, for admin course management, or outside the planner — the panel reads session, guest-profile and department data itself through hooks.

## What the consumer provides

- `planCourseIds: string[]` — required; ids already in the plan render as 추가됨 at `opacity-disabled` with dragging disabled.
- `onClickAdd?: (courseId: string, courseData: { code: string; name: string; credits: number; category?: RequirementCategory; departmentId?: string }) => void` — add buttons and quick-add tiles appear only when this is set.
- `focusedSemester?: { year: number; term: string } | null` — shows the focus banner and the per-row add buttons; `undefined`/`null` hides both.
- `isAddingCourse?: boolean` (default `false`) — disables every add button and paints it `gray-300`/`gray-500`; the card-view button reads `...`.
- No children. Give it a block container (the planner wraps it in a plain `div` with `scroll-margin-top: 72px`); it fills the width and sets its own `max-height` on the body. Internal state only: search (debounced 300 ms), `viewMode` (default `'list'`), `deptFilter`, year/semester/category filters, `isCollapsed`, `showCurriculumInfo`, `showCustomForm`.

## Accessibility

- Icon-only buttons (help, view toggle, collapse, add) carry Korean `aria-label`s; the chips are real `<button>`s with visible text but no `aria-pressed`, so the active filter is conveyed by color alone. No button sets `type`.
- No `focus-visible` styles anywhere in the panel; only the search `Input` shows a ring (`yu-cyan`, any focus). Keyboard users see browser defaults on everything else.
- Drag handles are the whole row/card (`touch-action: none`, dnd-kit attributes); the add buttons stop propagation so a click does not start a drag. No keyboard alternative to dragging beyond the add buttons.
- 10px badges, 11px labels and 20px add targets sit below common size guidance — kept from source. Collapsing hides the search, filters, banners and body without `aria-expanded`.
